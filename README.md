# تيّار — متجر الأجهزة الكهربائية

متجر إلكتروني متكامل مبني على **Python + Django 5 + PostgreSQL**، بواجهة عربية RTL،
ويشمل: كتالوج المنتجات، بحث وفلترة، سلة ودفع إلكتروني، إدارة مخزون متعدد المستودعات،
أوامر شراء وموردين، ولوحة تحكم بإحصائيات وتقارير.

---

## ١. التشغيل السريع

```bash
# 1) بيئة افتراضية
python -m venv .venv && source .venv/bin/activate      # ويندوز: .venv\Scripts\activate
pip install -r requirements.txt

# 2) الإعدادات
cp .env.example .env        # ثم عدّل SECRET_KEY وبيانات قاعدة البيانات

# 3) قاعدة بيانات PostgreSQL
createdb tayyar_db
# أو من psql:
#   CREATE DATABASE tayyar_db;
#   CREATE USER tayyar_user WITH PASSWORD 'strong-password';
#   GRANT ALL PRIVILEGES ON DATABASE tayyar_db TO tayyar_user;

# 4) الجداول والبيانات
python manage.py makemigrations accounts catalog inventory purchasing orders
python manage.py migrate
python manage.py seed_demo          # بيانات تجريبية + مستخدم admin
python manage.py runserver
```

بعدها:

| المسار | الوصف |
|---|---|
| `/` | واجهة المتجر |
| `/manage/` | لوحة تحكم المشرفين |
| `/secure-admin/` | لوحة Django الأصلية |

مستخدم البذرة: `admin` / `Admin12345!` — **غيّر كلمة المرور فوراً**.

## ٢. بنية المشروع

```
config/          الإعدادات والروابط الجذرية
apps/
  accounts/      المستخدم المخصص، الدخول بالبريد أو الاسم، العناوين
  catalog/       التصنيفات، العلامات، المنتجات، الصور، التقييمات، البحث والفلترة
  inventory/     المستودعات، الأرصدة، حركات المخزون، التحويل بين الفروع
  purchasing/    الموردون، أوامر الشراء، الاستلام وتحديث التكلفة
  orders/        السلة، الكوبونات، الطلبات، الفواتير، بوابة الدفع
  dashboard/     لوحة التحكم والتقارير والتصدير
templates/       قوالب RTL كاملة (متجر + لوحة تحكم)
static/css/      هوية بصرية واحدة بلا إطار CSS خارجي
```

### المفهوم المحوري: المخزون سجل حركات
كل تغيير في الرصيد يمر عبر `inventory.apply_movement()` الذي يسجّل حركة (إدخال، إخراج،
مرتجع، تسوية، تحويل، تالف) ويحدّث الرصيد في معاملة واحدة `atomic`. لا يُعدَّل الرصيد يدوياً
في أي مكان آخر، فيبقى السجل مطابقاً للواقع ويمكن تدقيقه دائماً.

- **دفع الطلب** ← خصم تلقائي من المخزون (مرة واحدة فقط، يحرسها حقل `stock_released`).
- **إلغاء أو استرجاع** ← إعادة الكميات تلقائياً.
- **استلام أمر شراء** ← إضافة الكميات وتحديث `cost_price` للمنتج، فتصبح تقارير الربح دقيقة.

## ٣. المزايا المنفَّذة

**المتجر**
- صفحة رئيسية بأقسام: العروض، اختيارات الفريق، وصل حديثاً، وشريط ثقة.
- بحث فوري مع اقتراحات أثناء الكتابة (AJAX).
- فلترة بالقسم، العلامة، كفاءة الطاقة، نطاق السعر، المتوفر فقط، وعليه خصم — مع ترتيب وترقيم صفحات.
- صفحة منتج بمعرض صور، تبويبات (وصف / مواصفات / تقييمات)، توفر حسب الفرع، ومقارنة حتى ٤ أجهزة.
- تقييمات المشترين بمراجعة قبل النشر، وقائمة رغبات.

**الحساب**
- تسجيل دخول بالبريد أو اسم المستخدم، تسجيل جديد، استعادة وتغيير كلمة المرور.
- عناوين متعددة مع عنوان افتراضي، طلباتي وتفاصيل كل طلب، وفاتورة قابلة للطباعة.

**السلة والدفع**
- سلة للزائر تُدمج تلقائياً في سلة الحساب بعد تسجيل الدخول.
- كوبونات (نسبة أو مبلغ، حد أدنى، تاريخ انتهاء، حد استخدام).
- شحن مجاني فوق حد معيّن، وضريبة قيمة مضافة محسوبة.
- ثلاث طرق دفع: بطاقة عبر **Stripe Checkout**، الدفع عند الاستلام، تحويل بنكي.
- تأكيد الدفع عبر **Webhook** موقّع (لا يُعتمد على صفحة النجاح وحدها).
- تحقق من توفر المخزون قبل إتمام الطلب.

**لوحة التحكم `/manage/`**
- مؤشرات: مبيعات اليوم والشهر، نسبة النمو، المشتريات، قيمة المخزون.
- رسم بياني للمبيعات مقابل المشتريات (Chart.js).
- الطلبات: بحث، تصفية بالحالة، تحديث الحالة ورقم الشحنة، وربح كل طلب.
- المنتجات: إضافة وتعديل وإخفاء، مع عرض التكلفة والهامش والرصيد.
- المخزون: الأرصدة لكل مستودع، تنبيه إعادة الطلب، حركة يدوية، تحويل بين المستودعات، وسجل الحركات.
- المشتريات: أوامر شراء بأصناف متعددة، واستلام بضغطة واحدة.
- التقارير: أداء شهري، مبيعات حسب القسم والمدينة، أفضل المنتجات ربحاً، أفضل العملاء، وتصدير CSV.

## ٤. تفعيل الدفع بالبطاقة

1. أنشئ حساباً على Stripe واحصل على المفاتيح.
2. ضع `STRIPE_PUBLIC_KEY` و`STRIPE_SECRET_KEY` في `.env`.
3. أضف Webhook على `https://your-domain/cart/payment/webhook/` لحدث
   `checkout.session.completed`، وضع سرّه في `STRIPE_WEBHOOK_SECRET`.

> للسوق السعودي والخليجي يمكن استبدال طبقة `apps/orders/payments.py` ببوابة محلية
> (مدى عبر Moyasar أو Tap أو HyperPay) — الملف مصمم كطبقة واحدة معزولة، فالتبديل
> يقتصر على دالتَي `create_checkout_session` و`confirm_stripe_session`.

## ٥. النشر على خادم إنتاج

```bash
DEBUG=False
ALLOWED_HOSTS=your-domain.com
CSRF_TRUSTED_ORIGINS=https://your-domain.com

python manage.py collectstatic --noinput
gunicorn config.wsgi:application --bind 0.0.0.0:8000 --workers 3
```

عند `DEBUG=False` تُفعَّل تلقائياً: تحويل إجباري إلى HTTPS، كوكيز آمنة، HSTS لسنة،
منع تضمين الصفحة في إطار، ومنع تخمين نوع المحتوى. ضع Nginx أمام Gunicorn لملفات
الوسائط (`/media/`) وشهادة TLS، وخذ نسخة احتياطية دورية من قاعدة البيانات.

## ٦. اقتراحات للمرحلة التالية

- ربط شركة شحن (سمسا / أرامكس) لتوليد بوليصة وتتبع تلقائي.
- فاتورة ZATCA إلكترونية مع رمز QR ومطابقة المرحلة الثانية.
- إشعارات واتساب أو رسائل نصية عند تغيّر حالة الطلب.
- تعدد اللغات (عربي/إنجليزي) عبر `django-modeltranslation`.
- Celery + Redis لإرسال البريد ومهام التقارير الثقيلة خارج دورة الطلب.
- اختبارات آلية لمسار الشراء ولمنطق المخزون (`pytest-django`).
